# Instant Replay for OBS

Мгновенный повтор («повтор гола») для OBS Studio в духе панели Replay в vMix: оператор жмёт одну
кнопку, в эфир уходят последние секунды программного микса — при необходимости замедленно, — после
чего эфир автоматически возвращается на живую картинку.

Статус: **v2** — буфер программы и до трёх камер, повтор с любого ракурса и замедлением,
переход в эфир с автовозвратом, автосохранение клипов в MP4. Ждёт прогона на эфирном ПК.

## Как пользоваться

1. View → Docks → **Instant Replay** — панель оператора.
2. Буфер стартует сам при запуске OBS и непрерывно держит последние секунды **программного
   микса** (то, что видит зритель). Индикатор сверху показывает заполнение, разрешение, расход
   RAM и время копирования кадра.
3. **MARK** — зафиксировать момент. Берутся последние «Длина повтора» секунд, заканчивающиеся за
   «Отступ от эфира» секунд до живого края (0 — по самый край). Событие появляется в списке.
4. **Скорость** 25/50/75/100 % — переключается и **во время** повтора.
5. **PLAY TO PROGRAM** (или двойной клик по событию) — эфир переходит на сцену `Instant Replay`
   текущим транзишеном, играет повтор и возвращается на прежнюю сцену. **STOP** прерывает повтор
   и возвращает эфир сразу.

6. **Ракурс** «Программа / Кам 1 / Кам 2 / Кам 3» — переключается и во время повтора, позиция
   сохраняется. Камеры — это сцены OBS, отмеченные галочками в группе «Камеры»; каждая
   буферизуется отдельно в выбранном разрешении (540p/720p/1080p). Кнопка камеры неактивна,
   если камера не была включена на момент клипа.

Сцена `Instant Replay` создаётся автоматически при первом показе. Пока повтор в эфире, запись во
все кольца стоит на паузе — иначе повтор попал бы в буфер, — поэтому после возврата индикатор
заполнения снова набирает секунды.

### Сохранение клипов

При каждом MARK клип **программного микса** в фоне кодируется в MP4 (H.264) и кладётся в
`<папка>/YYYY-MM-DD/HH-MM-SS_<событие>-NN.mp4`. Папка по умолчанию — папка записи OBS, можно
указать свою. Статус («сохраняется 45 %», «сохранено», «обрезано», ошибка) виден в списке событий.

Буфер держит лишь последние секунды, поэтому «сохранить после игры» невозможно — сохранение
происходит в момент MARK. Длина клипа ограничена «буфер − отступ − 2 с»: кольцо продолжает
писать под экспортом, и запас в 2 с нужен, чтобы энкодер успел стартовать раньше перезаписи
первых кадров. Энкодер «Авто» выбирает x264 (veryfast, CRF 18, половина ядер), если стрим идёт на
NVENC, и h264_nvenc — если стрим на x264 и NVENC есть в сборке FFmpeg.

### Память

Панель считает суммарный размер колец и сравнивает с бюджетом (половина свободной физической
памяти). NV12 при 50 к/с и 12 с: программа 1080p — 1.87 ГБ, камера 720p — 0.83 ГБ, камера
1080p — 1.87 ГБ, камера 540p — 0.47 ГБ. Три камеры в 1080p на 12 ГБ RAM не влезают — по умолчанию
720p.

### Горячие клавиши

Комбинации не назначены по умолчанию — задайте их в Настройки → Горячие клавиши. Имена для
obs-websocket и Stream Deck (`TriggerHotkeyByName`):

| Имя | Действие |
|---|---|
| `instant_replay.mark` | зафиксировать момент |
| `instant_replay.play_last` | выдать выбранный повтор в эфир |
| `instant_replay.stop` | остановить повтор и вернуться в эфир |
| `instant_replay.speed_cycle` | перебор скоростей 25 → 50 → 75 → 100 |
| `instant_replay.angle_program` | ракурс — программа |
| `instant_replay.angle_1` … `angle_3` | ракурс — камера 1…3 |

## Что уже есть

- кольцевой буфер программного микса в RAM (`obs_add_raw_video_callback2`, без конверсии формата);
- до трёх камер: приватные `obs_view` с raw `obs_output`, GPU-даунскейл, общий бюджет памяти;
- переключение ракурса во время повтора по общему timestamp миксов;
- автосохранение клипов в MP4 через libavcodec/libavformat из obs-deps;
- источник `Instant Replay` — асинхронный, с покадровой выборкой и замедлением;
- сцена повтора, переход в эфир текущим транзишеном и автовозврат с watchdog;
- пауза записи на время повтора и метка разрыва в буфере;
- горячие клавиши с загрузкой биндингов из профиля;
- панель оператора: MARK, длина и отступ, скорости, список событий, PLAY/STOP, индикаторы;
- локализация en-US / ru-RU.

## Совместимость

Плагин собирается против **OBS 32.2.2 + Qt 6.11.1** (obs-deps `2026-07-15`) — ровно та версия,
что стоит на эфирной машине. libobs сравнивает major.minor и отвергает модули, собранные новее
рантайма, поэтому **минимальная версия OBS — 32.2**. На 30.x и 31.x плагин не загрузится; если
понадобится поддержка более старых OBS, нужно понижать пин `obs-studio` в `buildspec.json`
(и тогда шаблон потребует правки: его аргумент `-A x64,version=...` исходники OBS 30.2.3 не
понимают).

## Сборка

### Windows (продакшен)

Собирается в GitHub Actions (`windows-2022`, Visual Studio 17 2022). На каждый тег вида `X.Y.Z`
создаётся релиз с двумя файлами:

- `instant-replay-for-obs-<version>-windows-x64-installer.exe` — **установщик** (Inno Setup).
  Ставит плагин в `C:\ProgramData\obs-studio\plugins\instant-replay-for-obs\`, требует прав
  администратора, просит закрыть OBS, умеет удаляться через «Приложения и возможности».
  Установщик не подписан — SmartScreen покажет предупреждение «Неизвестный издатель»,
  нажмите «Подробнее → Выполнить в любом случае».
- `instant-replay-for-obs-<version>-windows-x64.zip` — то же плюс `.pdb`, для ручной установки:
  распаковать в `C:\ProgramData\obs-studio\plugins\`, чтобы получилось

```
C:\ProgramData\obs-studio\plugins\instant-replay-for-obs\bin\64bit\instant-replay-for-obs.dll
C:\ProgramData\obs-studio\plugins\instant-replay-for-obs\data\locale\en-US.ini
```

Путь `C:\Program Files\obs-studio\obs-plugins\64bit` устарел и использоваться не должен.

### macOS (разработка)

Полноценная локальная сборка на macOS требует **полного Xcode 16+**: и шаблон плагина, и исходники
OBS принудительно требуют генератор Xcode (`cmake/macos/compilerconfig.cmake`), Command Line Tools
недостаточно. Сборки под macOS в CI отключены — продакшен-платформа одна, Windows.

Без Xcode доступна быстрая проверка синтаксиса: она компилирует исходники с `-fsyntax-only`
против зафиксированных в `buildspec.json` заголовков OBS и фреймворков Qt.

```sh
build-aux/syntax-check.sh
```

Форматирование — как в OBS (`clang-format-19` и `gersemi` из `obsproject/tools`):

```sh
brew install obsproject/tools/clang-format@19 obsproject/tools/gersemi
zsh build-aux/run-clang-format
zsh build-aux/run-gersemi
```

## Проверка на эфирном ПК

Чек-лист после установки (OBS 32.2.x, Windows):

1. В логе OBS (Help → Log Files → View Current Log) есть `plugin loaded successfully` и строка
   `capture started: 1920x1080 NV12, 50.00 fps`, следом — размер буфера в кадрах, секундах и ГБ.
2. Панель View → Docks → Instant Replay открывается, после перезапуска OBS остаётся на том же
   месте.
3. Индикатор буфера набирает заданные секунды и встаёт на плато; расход RAM в диспетчере задач
   перестаёт расти.
4. При запущенном стриме/записи счётчик «Skipped frames due to encoding lag» в статистике OBS не
   растёт, а время копирования в панели держится ниже 1 мс. Если появились «медленных кадров» —
   уменьшите буфер или поставьте 1080p25.
5. MARK → PLAY TO PROGRAM: эфир уходит на сцену Instant Replay, играет повтор, возвращается на
   прежнюю сцену. Цвета повтора совпадают с живой картинкой.
6. Второй MARK сразу после возврата: в буфере **не** должно быть самого повтора.
7. Скорость 25 % во время повтора переключается без рывка.
8. Переключение сцены оператором во время повтора: плагин прекращает повтор и не перехватывает
   управление.
9. Смена сцен-коллекции и профиля во время работы не роняет OBS.
10. Закрытие OBS проходит без краша, в логе нет предупреждений плагина.
11. MARK → через несколько секунд в `<папка записи>/YYYY-MM-DD/` лежит MP4 длиной клипа, цвет как
    в эфире; MARK и сразу PLAY — файл всё равно полный.
12. Три камеры 720p включены: RAM на плато ≈ 4.4 ГБ, «rendering lag» в статистике OBS не растёт,
    в панели у камер нет «⚠ медленных кадров».
13. Переключение «Кам 1 → Кам 2 → Программа» во время повтора на 25 % — без рывка по позиции.
14. Удаление сцены камеры на лету: панель показывает «scene was removed», OBS не падает.
